## ADDED Requirements

### 需求:必须完成投影维度消融实验

系统必须在 Protocol-A split 上对比不同投影维度 $d \in \{32, 64, 128, 256\}$ 对 TRR 检索性能的影响。

#### 场景:投影维度消融评估
- **当** 运行投影维度消融脚本
- **那么** 脚本必须对每个维度 d：(1) 使用 PCA 将 Wav2Vec2 768-dim 投影至 d-dim；(2) 计算 Gram matrix（d×d）；(3) 在 Protocol-A 上 top-1 检索；(4) 报告 L2, Acc@0.1, Recall, Cosine, Module

### 需求:必须完成层选择消融实验

系统必须在 Protocol-A split 上对比不同 Wav2Vec2 层组合对 TRR 性能的影响，包括：single layer {4}, {5}, {6}；当前组合 {4,5,6}；deep layers {7,8,9}；all-layer average。

#### 场景:层选择消融评估
- **当** 运行层选择消融脚本
- **那么** 脚本必须对每个层组合：(1) 提取对应层的特征；(2) 投影 + Gram matrix；(3) 在 Protocol-A 上 top-1 检索；(4) 报告五项指标

### 需求:论文必须包含消融实验结果表

论文 Sec 4（Experiments）必须新增消融实验子节，包含投影维度和层选择的结果表格。

#### 场景:消融表格呈现
- **当** 读者阅读消融实验子节
- **那么** 必须看到两个表格：(1) 投影维度消融表（4 行：d=32/64/128/256）；(2) 层选择消融表（6 行：{4}/{5}/{6}/{4,5,6}/{7,8,9}/all-layer）

### 需求:必须明确投影矩阵 P 的来源

论文 Sec 4（Methodology → TRR）必须明确说明投影矩阵 P 的具体实现方式（PCA/随机/学习），并注明 PCA 的拟合数据来源（仅 KB 数据，不包含 test queries）。

#### 场景:P 的说明呈现
- **当** 读者阅读 Algorithm 1 或其文字描述
- **那么** 必须看到明确的文字: "线性投影 P 通过在知识库音频的 Wav2Vec2 激活上拟合 PCA 得到"（或等价表述），并注明这避免了测试集泄露
