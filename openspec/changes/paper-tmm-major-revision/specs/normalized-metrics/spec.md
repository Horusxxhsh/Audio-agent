## ADDED Requirements

### 需求:必须实现归一化参数度量

评估系统必须支持 min-max 归一化模式：对每个参数按其 DSP 物理范围 $[l_i, u_i]$ 归一化至 [0,1] 后计算 L2, Acc@0.1 等指标。

#### 场景:归一化度量计算
- **当** 使用归一化模式运行评估
- **那么** 系统必须：(1) 从 `PluginAudioParameters.h` 或等价配置读取每个参数的 [min, max] 范围；(2) 对 ground-truth 和 predicted 参数向量进行 min-max 归一化；(3) 计算归一化后的 L2, Acc@0.1, Recall, Cosine, Module

### 需求:论文主表必须报告归一化指标

论文 Protocol-A 主表必须包含归一化后的指标，或在正文使用归一化指标、raw 指标移至补充材料。

#### 场景:归一化指标在正文呈现
- **当** 读者阅读 Protocol-A 主结果
- **那么** 必须能看到归一化后的 L2（值域在 [0,1] 量级）和 Acc@0.1（阈值相对于归一化范围）

### 需求:必须报告 per-parameter 误差分布

论文或补充材料必须包含 per-parameter 级别的误差分析，展示不同参数类型（频率、增益、开关等）的误差分布。

#### 场景:per-parameter 分析呈现
- **当** 读者阅读 per-parameter 分析
- **那么** 必须看到：(1) 按参数类别分组的平均误差；(2) 至少一个具体预设的 ground-truth vs TRR-retrieved vs baseline-retrieved 参数值对比案例

### 需求:L2 量级必须有具体解读

论文正文必须在报告 L2 数值后，给出至少一个具体案例来帮助读者理解 L2=X 在实际参数空间中意味着什么。

#### 场景:L2 案例解读
- **当** 读者首次看到 L2 数值
- **那么** 论文必须紧接给出类似"例如，L2=8.05 对应于一个典型预设中频率参数偏差 XX Hz、增益参数偏差 XX dB"的具体映射
