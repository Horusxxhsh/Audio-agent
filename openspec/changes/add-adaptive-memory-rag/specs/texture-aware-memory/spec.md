## 新增需求

### 需求:记忆三元组存储协议
系统必须能够持久化存储用户的音频偏好记录。每条记录（即记忆条目）必须包含以下三个核心组件：(1) 输入音频的 TRR Gram Matrix 向量；(2) 原始自然语言查询文本；(3) 经过用户确认或修正后的 DSP 参数字典。

#### 场景:成功保存记忆
- **当** 用户（或仿真脚本）确认了一组 DSP 参数并选择“保存预设”时
- **那么** 系统必须在 ChromaDB 的 `user_preference_memory` 集合中创建一个新条目，存储对应的 TRR 向量、文本描述和参数映射

### 需求:记忆优先检索逻辑
在执行检索任务时，系统必须同时搜索静态知识库和记忆缓冲区。如果记忆缓冲区中存在记录，其推荐优先级必须高于静态知识库。

#### 场景:基于纹理找回记忆
- **当** 输入音频的 TRR 向量与记忆库中某条记录的余弦相似度超过 0.95 时
- **那么** 系统必须将该记忆条目作为 Top-1 结果返回，即便静态知识库中有更高相似度的“官方”预设

### 需求:记忆库持久化
记忆库必须支持跨会话持久化，禁止在程序重启后丢失用户偏好。

#### 场景:跨会话加载
- **当** `AudioRAGSystem` 初始化时
- **那么** 系统必须自动挂载现有的 `vector_db` 目录并验证 `user_preference_memory` 集合的有效性
