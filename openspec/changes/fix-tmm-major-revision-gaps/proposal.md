## 为什么

当前 TMM 修订稿面临的核心风险不是单点实验缺失，而是证据链叙事在多文档之间的稳定性不足。主文、补充材料与实验报告在若干位置存在潜在口径漂移，fusion 相关叙事又与当前收敛到 TRR 主证据链的方向并行存在，这会增加审稿阶段对一致性与可复现性的质疑成本。与此同时，部分历史有效图表在迭代中出现了“图在文中缺位或图文映射不完整”的问题，实验 setup 表述也混入了脚本文件名等工程实现细节，不利于论文方法学表达的规范性。基于这些风险，本变更需要以最小范围重构文稿证据结构，使论文结论在当前仓库内可核验、可答辩、可持续维护。

## 变更内容

本提案将论文实验主叙事收敛到单一可验证口径，要求主实验对比表与指定实验报告逐项对齐，并在发现冲突时输出明确差异记录而不是保留并行数字来源。文稿层面将下调 fusion 在本轮中的证据角色，不再将其作为主结论支撑，同时恢复与主线一致且仍有效的历史图表与对应描述，确保图文关系连续。论文写作规范方面，实验 setup 将从工程实现细节中抽离，避免出现脚本文件名或临时文件命名。为保障重投执行效率，本提案还要求同步产出可提交的审稿回应包，包括逐条回应文档与章节级修订清单，并与实际文稿改动建立追踪映射。所有回应文稿与论文段落级改写在执行阶段必须通过 `scientific-writing` skill 流程生成，并与证据核对步骤搭配执行。

## 功能 (Capabilities)

### 新增功能

新增 capability `paper-report-alignment-audit`，用于约束论文主实验结果与指定报告的逐项一致性核查流程，并要求给出一致项与差异项的可审计输出。新增 capability `tmm-revision-response-package`，用于约束审稿回应文档的结构化产出，确保每条回应都可以映射到具体章节修订动作，从而降低“回应与正文脱节”的重投风险。

### 修改功能

本提案将修改 `trr-analysis-section`，使主结果表、TRR 相关图表与实验解释统一到同一协议口径并保持可追溯。`mushra-subsection` 也将被修改，以确保听测结果作为补充证据的定位清晰，并在命名和统计口径上维持跨段一致。`fusion-analysis-section` 将被修改为“非主证据链”角色，避免 fusion 结果继续承担本轮主结论的量化支撑。`paper-ieee-template` 将同步补充约束，明确实验 setup 不得出现脚本文件名或一次性工程细节描述。

## 影响

该变更将直接影响论文文档 `Paper/content.tex` 与 `Paper/supplementary.tex` 的实验叙事与方法表述，并影响审稿回应文档 `Paper/TMM_Response_to_Reviewers.md` 与 `Paper/TMM_Revision_Checklist.md` 的结构化维护。证据对照层面将使用 `Experiments/AblationStudies/retrieval_comparison_report.md` 作为指定核对入口，同时在执行任务中增加与 canonical Protocol-A 产物的复核步骤，以规避来源争议。OpenSpec 层面将新增两个 capability 增量文件并修改四个既有 capability，使本轮修订目标在规范、任务和文稿三层保持一致。
