## 上下文

本次变更不是算法研发，而是投稿前证据治理与文稿收敛工程。当前仓库已有多轮实验与论文改写，风险点集中在：
- 主文、补充材料与实验报告之间可能存在数字口径漂移；
- fusion 相关叙事与当前“TRR 主证据链”收敛方向冲突；
- 历史有效图表被误删或图文映射不完整；
- 实验 setup 混入脚本文件名等实现细节，不符合论文写作规范；
- 审稿意见回复与文稿改动未形成可追踪映射。

该类问题跨越多个文档与 capability（`trr-analysis-section`、`mushra-subsection`、`fusion-analysis-section`、`paper-ieee-template`），属于典型跨域规范修复。

## 目标 / 非目标

**目标：**
- 建立“论文主实验表 ↔ 指定实验报告”的一一对应检查机制，并输出一致/差异结论。
- 将主实验叙事固定为 TRR 检索主线，移除 fusion 作为主结论证据。
- 恢复并保留与当前主线一致的历史有效图表与实验描述。
- 规范实验 setup 表述，禁止脚本文件名进入论文描述。
- 产出可直接用于重投的审稿回应包（逐条回应 + 修订清单）。

**非目标：**
- 不新增模型训练与新实验结果。
- 不修改实时音频引擎、检索算法实现或推理代码。
- 不在本变更中承诺完成跨域大规模新数据实验（该项仅列为重投前计划）。

## 决策

### 决策 1：采用“单主证据链”收敛策略

- 选择 TRR objective 表作为主证据链，要求与指定报告逐项一致。
- fusion 从“结果主证据”降级为“背景/限制讨论”或移除。
- 理由：当前审稿核心风险是证据冲突而非方法缺失，先保证可复现与可答辩。

**备选方案**
- 保留 TRR + fusion 双主线并同时补全全部对照。否决：会扩大不一致面，且超出当前修稿窗口。

### 决策 2：图表采用“保留有效、剔除冲突”

- 恢复与主线一致的历史图（TRR 层选择、听测分组图），并同步段落解释。
- 删除或不引用与当前主线冲突的实验图表。
- 理由：可最大化保留已有实验资产，同时避免图文矛盾。

### 决策 3：引入文稿-报告一致性审计能力

- 新增 capability `paper-report-alignment-audit`，将“核对动作”本身规范化。
- 要求输出差异清单，避免“口头确认一致”但无审计记录。
- 理由：审稿阶段需要可追踪证据，而不是一次性人工对照。

### 决策 4：引入审稿回应包能力

- 新增 capability `tmm-revision-response-package`，将 response 文档与实际改动建立映射。
- 理由：减少“回应与正文不一致”风险，提升重投效率。

### 决策 5：论文 setup 与工程实现解耦

- 修改 `paper-ieee-template` 相关要求：实验 setup 仅保留可复现实验协议，不出现脚本文件名。
- 理由：文件名属于工程细节，不是论文方法学要素，且易引发审稿误解。

### 决策 6：写作执行采用“审查 + scientific-writing”组合流程

- 回应文稿与论文叙述性改写必须在执行阶段显式调用 `scientific-writing` skill 产出段落化文本。
- 写作前必须完成证据一致性核对，确保写作素材与最终数字口径一致。
- 理由：把“证据核对”和“学术写作”绑定为同一执行流水线，可同时降低事实漂移与文风不统一风险。

## 风险 / 权衡

- [风险] 移除 fusion 主叙事后，论文“多模块贡献”表面上变少。
  - 缓解：在讨论与限制中诚实界定边界，并强调 TRR 主结果的可复现性。

- [风险] 依赖 `retrieval_comparison_report.md`（legacy 标注）可能带来来源争议。
  - 缓解：任务中强制追加与 canonical Protocol-A 产物复核，并记录差异。

- [风险] 恢复历史图时可能引入编号或引用错位。
  - 缓解：增加图表编号/引用一致性检查步骤。

- [权衡] 本次先修“可信度”而非“新增性能”。
  - 说明：优先满足重投可答辩，再安排新增实验。

## Migration Plan

1. 在 OpenSpec 中落地新增/修改 capability（含移除 fusion 主证据要求）。
2. 执行论文文档改写：
   - 对齐主表与报告；
   - 恢复有效图表；
   - 清理 setup 文件名；
   - 调整 fusion 表述。
3. 生成并更新审稿回应包文档。
4. 执行一致性审计并记录结果（一致项/差异项）。
5. 运行 LaTeX 编译与引用检查，确认无新增结构性错误。

**回滚策略**
- 文稿层面：按文件粒度回滚（`Paper/content.tex`、`Paper/supplementary.tex`、回应文档）。
- 规范层面：按 capability 增量文件粒度回滚，不影响运行时代码。

## Open Questions

- fusion 是否保留一句“方法存在但本轮不作为核心证据”的限制性说明，还是彻底移除全部出现位置？
- 审稿回应包是否需要额外加入“每条回应对应的行号变更映射表”？
