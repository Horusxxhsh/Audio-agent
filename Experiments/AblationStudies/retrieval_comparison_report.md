| **TRR (Texture Resonance Retrieval)** | 基于音频纹理共鸣的检索（Gram Matrix）           |

## 5. 计算方法说明

### 5.1 模块一致性 (Module Consistency)

使用Jaccard相似度计算：

```
Module Score = |A ∩ B| / |A ∪ B|
```

其中：

- A = GT中激活的模块集合（键名以"On"结尾，如CompressorOn）
- B = 检索结果中激活的模块集合

**判断逻辑**: 单纯看参数键名是否以"On"结尾，不检查参数值大小

### 5.2 余弦相似度 (Cosine Similarity)

衡量参数向量的方向一致性：

```
Cosine = (A · B) / (||A|| × ||B||)
```

值范围：[-1, 1]，其中1.0表示方向完全一致。

### 6.2 检索质量分析

本实验使用211个测试样本，全面评估了各检索方法在真实场景中的性能表现：

| 方法                    | L2误差  | 模块一致性 | 检索质量评价                               |
| ----------------------- | ------- | ---------- | ------------------------------------------ |
| **TRR**           | 0.3064  | 0.9574     | ✓ 优秀 - 模块一致性接近完美               |
| **Wav2Vec-RAG**   | 0.3625  | 0.9116     | ✓ 良好 - 音频相似度检索有效               |

**关键发现**：

1. **TRR表现最优**：L2误差最低（0.3064），模块一致性优秀（95.74%），证明基于音频纹理的检索最有效
2. **Wav2Vec-RAG表现良好**：L2误差0.3625，模块一致性91.16%，音频嵌入向量检索是可行的替代方案
3. **Text-RAG存在局限**：L2误差0.4573，模块一致性86.25%，纯文本检索无法捕捉音频特征
4. **FeatureNN-RAG显著改善**：经参数修复后，L2误差从8.63降至1.17（降低86.4%），但仍不如其他方法
5. **Pure LLM完全失败**：L2误差高达13.65，部分样本出现极端错误（Classic Plexi: L2=74.40, Brown Sound: L2=70.94, Saturated Rhythm: L2=75.13），充分证明了RAG检索的必要性

**极端错误样本分析**：

- **纯LLM无法准确生成参数值**（即使学会了ON/OFF规律）
- **RAG检索提供的真实参考参数至关重要**
- **必须使用检索增强生成(RAG)而非纯LLM生成**

### 6.3 实际应用建议

- **综合性能最优**: TRR在所有主要指标上全面领先（L2=0.3064, 准确率=72.53%, 召回率=69.90%, 余弦相似度=0.8376, 模块一致性=0.9574）
- **音频嵌入方法**: Wav2Vec-RAG性能良好（L2=0.3625），适合需要音频相似度的场景
- **快速部署**: Text-RAG性能中等（L2=0.4573），无需音频特征提取
- **模块一致性最高**: FeatureNN-RAG经修复后有所改善（L2=1.17），模块一致性达到96.02%，在所有方法中最高
- **禁止使用**: 纯LLM直接生成完全失败（L2=13.65），必须使用RAG检索
- **LLM增强**: 在TRR检索基础上使用LLM进行参数微调，可进一步纠正模块级检索误差（见第7节）

### 6.4 RAG必要性验证：纯LLM直接生成 vs RAG检索

为了证明RAG检索的必要性，我们添加了**纯LLM直接生成**方法的对比实验：

| 对比项               | 纯LLM直接生成 | TRR检索 | 改进幅度            |
| -------------------- | ------------- | ------- | ------------------- |
| **L2误差**     | 13.6520       | 0.3064  | **97.8% ↓**  |
| **准确率**     | 0.4361        | 0.7253  | **66.3% ↑**  |
| **召回率**     | 0.2127        | 0.6990  | **228.6% ↑** |
| **余弦相似度** | 0.3779        | 0.8376  | **121.6% ↑** |
| **模块一致性** | 0.7053        | 0.9574  | **35.7% ↑**  |

**关键发现**：

1. **纯LLM的严重缺陷**：虽然模块一致性达到70.53%，但L2误差极高（13.65），参数值生成完全失败

   - Classic Plexi样本L2误差高达74.40，严重偏离真实参数
   - Brown Sound样本L2误差高达70.94，严重偏离真实参数
   - Saturated Rhythm样本L2误差高达75.13，严重偏离真实参数
2. **RAG的必要性**：

   - RAG检索相比纯LLM生成，L2误差降低**97.8%**
   - 准确率提升66.3%，召回率提升228.6%，余弦相似度提升121.6%，模块一致性提升35.7%
   - **结论**: 仅靠LLM无法生成准确的吉他音色参数，必须使用RAG检索
3. **Few-shot学习的局限性**：

   - 纯LLM虽然通过Few-shot（5个示例）学会了部分模块开关规律
   - 但无法准确预测每个参数的具体数值（如阈值、比例等）
   - RAG检索提供了真实的参考参数，这是生成高质量结果的关键
4. **LLM使用的API和模型**：

   - **模型**: DeepSeek-Chat (`deepseek-chat`)
   - **API**: https://api.deepseek.com
   - **客户端**: OpenAI 兼容库
   - **Few-shot示例**: 5个完整示例（Dry Funk Rhythm, Vintage Tweed Breakup, Reverse Psychedelic Delay, Math Rock Crystal Cleans, Saturated Drive Rhythm）

## 8. 鲁棒性测试实验 (Robustness Testing)

### 8.1 实验背景

为了验证混合检索系统在真实应用场景中的鲁棒性，我们设计了两个极端噪声场景的实验：

1. **文本模糊场景**: 模拟用户无法提供准确风格描述的情况
2. **音频噪声场景**: 模拟音频质量受损的情况

### 8.2 文本模糊场景实验 (Text Vague Experiment)

**实验设置**: 使用模糊词（如 "warm" 等）进行文本检索，模拟用户描述不准确的情况。

**表 8a: 文本模糊场景下的性能对比 (N=5)**

| 方法                          | L2误差↓        | 准确率↑       | 召回率↑       | 余弦相似度↑   | 模块一致性↑   |
| :---------------------------- | --------------- | -------------- | -------------- | -------------- | -------------- |
| **Text+LLM**            | 29.28           | 0.62           | 0.43           | 0.51           | 1.00           |
| **Hybrid(α=0.15)+LLM** | **0.26**  | **0.82** | **0.71** | **0.81** | **1.00** |
| **改进幅度**            | **99.1%** | **+32%** | **+65%** | **+60%** | -              |

**关键发现**:

- 当文本查询模糊时，纯文本检索几乎失效（L2=29.28）
- 增加音频权重（α=0.15，即85%音频权重）能显著补偿文本信息损失
- L2误差从29.28降低到0.26，提升**99.1%**
- 动态权重调节机制成功实现了跨模态信息互补

### 8.3 音频噪声场景实验 (Audio Noise Experiment)

**实验设置**: 给TRR向量添加强噪声（noise_level=5.0），模拟音频质量严重受损的情况。

**表 8b: 音频噪声场景下的性能对比 (N=5)**

| 方法                          | L2误差↓        | 准确率↑       | 召回率↑        | 余弦相似度↑   | 模块一致性↑   |
| :---------------------------- | --------------- | -------------- | --------------- | -------------- | -------------- |
| **TRR+LLM**             | 29.36           | 0.41           | 0.25            | 0.41           | 1.00           |
| **Hybrid(α=0.85)+LLM** | **0.28**  | **0.72** | **0.62**  | **0.78** | **1.00** |
| **改进幅度**            | **99.1%** | **+75%** | **+148%** | **+91%** | -              |

**关键发现**:

- 当音频质量严重受损时，纯音频检索性能大幅下降（L2=29.36）
- 增加文本权重（α=0.85，即85%文本权重）能显著补偿音频信息损失
- L2误差从29.36降低到0.28，提升**99.1%**
- 混合检索在极端噪声条件下依然保持稳定性能

### 8.5 鲁棒性测试结论

**核心优势**:

1. **信息互补**: 当一个模态质量下降时，自动增加另一个模态的权重
2. **鲁棒性**: 在两种极端噪声场景下都保持稳定的低误差（<0.30）
3. **自适应**: 无需人工干预，系统自动检测并响应输入质量变化

**实际应用价值**:

- 用户可能无法提供准确的风格描述（文本模糊场景）
- 录制音频可能存在质量问题（音频噪声场景）
- 混合检索系统能够在两种情况下都保持高性能，显著优于单模态检索
